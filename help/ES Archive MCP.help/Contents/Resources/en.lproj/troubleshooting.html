Troubleshooting

The archive tools do not appear in my assistant

For Claude Desktop:

  1. Check the extension is installed and enabled: Claude Desktop ▸ Settings ▸ Extensions should list ES Archive, switched on.
  2. If it is missing, reconnect: choose Help ▸ Connect ES Archive… here, click Connect, and approve the install when Claude Desktop asks.
  3. The tools arrive when a conversation starts — begin a fresh conversation after installing.
  4. If you had the app under its old name, remove any leftover ES Memory extension so only one archive is connected.

For ChatGPT, open the server from Settings ▸ Plugins ▸ MCPs and check that the command is the app's full executable path and that --author and the persona name are two separate argument rows — a single row holding both is passed as one argument, and the persona is silently ignored.

For LM Studio, confirm the configuration was pasted into Program ▸ Edit mcp.json unchanged, and that the loaded model supports tool use — one that does not will never call the tools, however well it is connected. If you have moved the app since connecting, copy the configuration afresh: it names the app's path at the moment you copied it.

Search finds nothing, or the wrong things

Semantic search matches an entry's summary, not its body. An entry stored without one has no vector, so it is invisible to search and appears as an isolated dot in Archive Scope. Open Archive Scope and read the Isolated count in the status line: if it is more than a handful, that is your answer. Ask your assistant to add summaries to those entries.

Right after a restore, or after entries arrive from another Mac through iCloud, vectors are still being computed — the app fills in any that are missing each time a session starts. Search over those entries sharpens over the next few moments. Watch the similarity edges appear in Archive Scope.

If you are searching for an exact string — a path, an error message, a name — ask for a pattern search instead. See What your AI can do.

The app quits the moment I open it

That is the app declining to run twice. An assistant session is already hosting the archive, and the copy you launched found nothing left to do — the running host owns the windows. Reach the app through that host instead: its status item in the menu bar, or its Dock icon if you use Dock mode. When no session is active, opening the app from Finder keeps it open as usual.

Entries are attributed to the wrong persona

Authorship comes from how the client launched the app. Reconnect the client so it carries the author you intend, then fold the mis-attributed records into the right persona with Merge… in Manage Personas…. Back up first.

My other Mac does not have the same entries

  • Both Macs must be signed into the same Apple Account with iCloud Drive on.
  • Sync is not instantaneous. Leave both awake and connected for a few minutes.
  • Entries that arrive from another Mac need their vectors computed locally before search reaches them.

If it still will not sync, back up on one Mac and restore on the other — Backing up and restoring. That works with no iCloud at all.

Archive Scope says "No entries yet"

The archive is empty for the persona you have selected. Check the persona picker at the bottom right and try All (witness). If that is empty too, nothing has been stored yet — import the demo archive from Help ▸ Connect ES Archive… to have something to look at.

Still stuck

Report it at github.com/apocryphx/ES-Archive/issues. Include your macOS version, the ES Archive MCP version, and which client you are connecting.
