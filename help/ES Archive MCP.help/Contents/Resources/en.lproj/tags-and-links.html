Types, tags and links

The three ways the archive organises itself.

All three are set by your assistant as it writes, not by you. Knowing what they mean makes Archive Scope far easier to read, and gives you something concrete to ask for — "tag that as a decision", "link this back to what we agreed in March".

Types

Every memory is classified. The type appears in the Archive Scope detail panel.

TypeWhat it holds
memoryWhat happened. The default.
thoughtWhat the assistant made of it.
referenceSomething factual and stable, worth looking up.
preferenceHow you like things done.
questionUnresolved, worth returning to.
decisionA commitment, with the reasoning that produced it.
reflectionStepping back to see the larger shape.
codeAn implementation worth keeping.
letterAddressed to someone.
dreamSpeculative — a design not yet built.
schemaDefines the structure of a typed record.

Tags

Tags are deliberately scarce. Nothing in ES Archive MCP extracts keywords automatically — a tag exists because the assistant judged it worth creating, which is what makes the tag list meaningful instead of a word-frequency table. Each tag has a kind:

person · place · project · principle · subset · session · research · thing (the uncategorised default)

The Tag Cloud tab in Archive Scope shows them sized by how many memories carry them. When the last memory holding a tag is erased, the tag is removed too, so the cloud never fills with empty labels.

Links

A link is a directional connection the assistant makes on purpose between two memories. Each one names the relationship with a short verb — elaborates, answers, corrects, revises, contradicts, disputes — and that verb is traversable: the archive can be asked for, say, only the places where one memory contradicts another.

In Archive Scope, links are the solid lines. The faint lines are not links at all: they are similarity edges the app computes for you, and they appear and disappear on their own as the archive changes.

Two different kinds of connection

Links are authored and permanent until removed. Similarity edges are derived from meaning and recomputed continuously. A memory can be strongly linked to something it bears no textual resemblance to, and vice versa — seeing both at once is the point of the graph.

Comments, references and revisions

  • Comments are notes added to a memory after it was written. They show up in the detail panel under marginalia, each with its author and date.
  • References point at something outside the archive — a URL, a document, a citation.
  • Revisions keep the earlier state of a memory when it is edited, so the history of a changing idea is not lost.
