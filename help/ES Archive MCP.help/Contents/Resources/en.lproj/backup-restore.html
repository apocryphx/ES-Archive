Backing up and restoring

Your own copy of the archive, in a single file.

Backing up

Choose File ▸ Back Up… (⇧⌘B) and pick a location. You get one .esarchive file holding every entry, tag and link, named with today's date — for example ES_Backup-2026-08-07.esarchive.

Vectors are deliberately left out. They are derived data, they are large, and they are rebuilt automatically after a restore.

iCloud is not a backup

iCloud sync keeps your Macs in step — which means a deletion syncs too. A .esarchive file is the only copy that holds still. Take one before anything irreversible: a restore, a persona merge, a large clean-up.

Restoring

Choose File ▸ Restore… (⇧⌘R), confirm, and choose the file. When it finishes you are told how many entries were processed, how many links were inserted, how many were already present, and how many were dropped because the entry at one end was not in the archive.

Restoring merges — it does not replace. The archive you have is kept, and the file's contents are added to it. Where the same record exists on both sides, the one with the newer modification date wins. Restoring the same file twice is harmless.

Vectors for the restored entries are regenerated in the background, so semantic search over them sharpens over the following moments rather than being ready instantly.

Moving to another Mac

If you use iCloud, do nothing: the archive is already there. Otherwise back up on the first Mac, copy the .esarchive file across, and restore on the second.

The demo archive

An empty archive demonstrates very little. Open Help ▸ Connect ES Archive… and click Import Demo Archive… to merge in a prepared set of entries, tags and links you can search, follow and look at in Archive Scope.

They arrive as ordinary entries. Nothing marks them as samples afterwards, so removing them later means deleting them individually — worth knowing before you add them to an archive you already care about. Adding them twice does no harm; matching records are recognised rather than duplicated.
